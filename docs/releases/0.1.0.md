# GeoLens 0.1.0

Release date: 2026-07-30

## Highlights

- FastAPI project, crawl, provider-analysis, citation, entity, score, and claim APIs.
- Next.js evidence dashboard with deterministic sample onboarding and MockProvider run.
- PostgreSQL schema managed by Alembic and an idempotent Acme Cloud sample seed.
- Redis/Celery crawl queue and a bounded, DNS-pinned, exact-host crawler.
- Provider-neutral adapters for mock, OpenAI, Gemini, and Perplexity responses.
- Disclosed deterministic visibility, citation, share-of-voice, entity, retrieval, and claim-risk
  formulas.
- Production multi-stage frontend image and non-root backend image.
- Five-service Compose topology with health/readiness gates and automatic migration startup.
- CI for linting, formatting, type checking, unit tests, PostgreSQL integration tests, frontend
  tests, production builds, Compose validation, and container builds.

## Release-candidate hardening

- Moved Celery enqueue off the async API event loop.
- Ended database transactions before provider and classifier network calls.
- Corrected multi-part provider citation offsets.
- Rejected unsafe provider citation links and independently sanitized frontend evidence links.
- Removed unused provider credentials from the crawl worker environment.
- Preserved exact response prompt/provider context for persisted claims.
- Stopped presenting unconfigured claims as model-classified risk.
- Added bounded prompt, provider-name, alias, and citation URL validation.

## Known limitations

This release has no authentication, tenant isolation, rate limiting, TLS termination, production
observability, historical-run UI, or bundled JavaScript renderer. Provider APIs may drift, and
live tests are opt-in. See [../limitations.md](../limitations.md) and
[../security.md](../security.md) before deployment.

## Upgrade

This is the first tagged schema series. Start the API container once against the target database;
its entrypoint applies Alembic revisions through `0003`. For deployments with multiple API
replicas, run migration as one serialized job instead of allowing every replica to migrate.
